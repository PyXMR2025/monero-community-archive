# Original Description
https://github.com/monero-project/monero/blob/0f84863feda75574788e15c9691abecf57bc3f8f/src/wallet/api/unsigned_transaction.cpp#L300

when testing offline signer wallets - i noticed cupcake had an issue with a pay-to-many transaction. they have a check to confirm [`(amts.length != addrs.length)`](https://github.com/cake-tech/cupcake/blob/83d2a14dfe095f8fe5ab4ffb467655aa0f17b111/lib/coins/monero/wallet.dart#L123) but are only given `dests[0]` where as amount returns [all](
https://github.com/monero-project/monero/blob/master/src/wallet/api/unsigned_transaction.cpp#L218-L227)

anonero also uses recipientAddress() . anonero-fork has provided a solution to move to [pay-to-many](https://codeberg.org/iuanv9/anonero-fork/commit/0bfb80471b5d7d125d6e57f976031ee4a33ce462)

reason for deprecation is this _could_ lead to a huge **gotcha** bug where consumers of the api using recipientAddress() only show dest[0] of a pay to many transaction - possibly leading to the cold wallet being drained. cupcake have protections against this but anonero does not (these are universal* cold signers so could be presented a pay-to-many transaction from a compatible wallet)

[monero-gui](https://github.com/monero-project/monero-gui/blob/9dc0c85c16da76cb3c79c0536a28c54c8a38ee66/src/libwalletqt/UnsignedTransaction.cpp#L90-L96
)  and [feather](https://github.com/feather-wallet/feather/blob/cbf966f5ba948b32fb76ad436ab7dca470239ccd/src/libwalletqt/UnsignedTransaction.cpp#L66-L72) are looping over the recipientAddress() is dead code?

monero-gui uses [m_confirmationMessage](https://github.com/monero-project/monero/blob/0232839913b13cf0ab0bb7ad25fff0c05f37d2fe/src/wallet/api/unsigned_transaction.cpp#L214) [here](https://github.com/monero-project/monero-gui/blob/9dc0c85c16da76cb3c79c0536a28c54c8a38ee66/pages/Transfer.qml#L1043) which contains all the destinations just fine.

## SNeedlewoods | 2026-07-15T14:20:58+00:00
As you identified `recipientAddress()` is unused by `monero-wallet-gui` and to ensure the GUI shows all recipients when signing a `UnsingedTransaction` it uses `confirmationMessage()`.
AFAICT, if we would remove `recipientAddress()` we would "force" Wallet API users to use `confirmationMessage()`, which is just one long string. IMO the pro for `confirmationMessage()`, that it also contains info about `fee` and `change` (otherwise there is currently no way to get the change amount from an `UnsignedTransaction`, but that function would be easy to add if needed) is outweighed by the con to force everyone to use this exact format, or having to deal with string manipulation to display only what they want.
Therefore I'd prefer to change `recipientAddress()` to return all recipients, to give Wallet API users more fine grained control:
```diff
std::vector<std::string> UnsignedTransactionImpl::recipientAddress() const 
{
    std::vector<string> result;
    for (const auto &utx: m_unsigned_tx_set.txes) {
        if (utx.dests.empty()) {
          MERROR("empty destinations, skipped");
          continue;
        }
-        result.push_back(cryptonote::get_account_address_as_str(m_wallet.m_wallet->nettype(), utx.dests[0].is_subaddress, utx.dests[0].addr));
+        for (const auto &u_dest : utx.dests)
+          result.push_back(cryptonote::get_account_address_as_str(m_wallet.m_wallet->nettype(), u_dest.is_subaddress, u_dests.addr));
    }
    return result;
}
```
