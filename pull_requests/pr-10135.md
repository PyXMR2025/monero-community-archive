# Original Description
See the comment above `fe_reduce_vartime` for an explanation of what its purpose is.

In the FCMP++ integration, `fe_reduce_vartime` is used in the `torsion_check_vartime` function discussed in #10134.

> As it is written above, it is our opinion the following code is fit for use. The round-trip
through fe_tobytes and fe_frombytes_vartime correctly contracts limb magnitudes back
into the precondition domain of fe_add/fe_sub

From Cypher Stack audit section 7 ([commit](https://github.com/cypherstack/fcmp-impl-audit/blob/d7de33d08c48a3c249629e47f71ea72c938a3404/FCMP_Code_Implementation_Audit.pdf))

## jeffro256 | 2026-07-02T17:14:26+00:00
If the precondition is `|h| bounded by 1.1*2^26,1.1*2^25,1.1*2^26,1.1*2^25,etc.`, then this function isn't vartime, even though it's calling a vartime function, since `fe_frombytes_vartime()` is only vartime in whether or not the field element is valid or not. It also doesn't have to return a value if the precondition holds (same as `fe_add()`, `fe_sub()`, `fe_mul()`, etc). Would the auditors be okay with switching the function signature to `void fe_reduce()` since the precondition is documented?
