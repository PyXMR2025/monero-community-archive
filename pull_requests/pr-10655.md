# Original Description
Replaces #10636 

One issue with the other approach is that it doesn't automatically create new caches on merges, which will eventually cause them to become stale. With this PR, caches are created for every merge and pull requests will use the most recent cache from their respective branch. It also prevents caches from being created on the pull request scope, which is primarily responsible for our cache thrashing problem.

I have looked for a more concise way to implement this, but haven't found it.
