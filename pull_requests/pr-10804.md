# Original Description
This avoids a few unaligned word accesses in the crypto code paths.

The main change is keeping `hash_state` and `cn_slow_hash_state` naturally aligned before they are used through their `uint64_t` members. It also switches byte-buffer word loads/stores to `memcpy` in Keccak, CryptoNight variant 1 nonce handling, and the CryptonightR JIT patcher.

This should help with the sparc64 SIGBUS reports in #10076. I do not have sparc64 access, so I validated the affected paths locally with alignment sanitizer too.

Tests:
- `cmake --build build-normal-crypto --target cncrypto-tests monero-wallet-crypto-bench unit_tests hash-tests -j2`
- `./build-normal-crypto/tests/crypto/cncrypto-tests tests/crypto/tests.txt`
- `./build-normal-crypto/tests/unit_tests/unit_tests --gtest_filter='keccak.*'`
- `./build-normal-crypto/tests/monero-wallet-crypto-bench 10`
- `ctest --test-dir build-normal-crypto -R '^hash-(fast|slow|slow-1|slow-2|slow-4|variant2-int-sqrt)$' --output-on-failure -j2`
- `cmake --build build-align-crypto --target cncrypto-tests unit_tests hash-tests -j2`
- `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1 ./build-align-crypto/tests/crypto/cncrypto-tests tests/crypto/tests.txt`
- `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1 ./build-align-crypto/tests/unit_tests/unit_tests --gtest_filter='keccak.*'`
- `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1 ctest --test-dir build-align-crypto -R '^hash-(fast|slow|slow-1|slow-2|slow-4)$' --output-on-failure -j2`
- 32-bit compile check for the `hash_state` alignment assertion
