## jeffro256 | 2026-09-19T04:50:03+00:00
I'd rather keep this line as-is. Until we know whether what a new added input type is, we don't know if it would prevent an inflation bug. For example, let's say that we added a `txin_key_image` type to save 2 bytes per input for FCMP++ tx serialization. If we continue here, then boom inflation bug. If we always assume "spent" for non-`txin_to_key` inputs, then during development, we will find this code blocking txs from being accepted very quickly, but at least the monetary supply is intact.
