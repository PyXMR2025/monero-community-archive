# Original Description
## What this adds

This adds functional coverage for the split `/get_transactions` response using a confirmed CARROT v2 transaction already created by the existing transfer test.

The test fetches the same transaction in full and split form, then checks that:

- `pruned_as_hex` and `prunable_as_hex` are both present
- concatenating both parts reproduces the original transaction blob byte-for-byte
- the full and split responses preserve the same transaction ID
- the decoded transaction is version 2 and contains CARROT outputs

## Why

External wallets, indexers, and view-only scanners may consume the split response instead of the complete transaction blob. Both split fields can look individually valid while still failing to reconstruct the canonical transaction if the RPC serialization path regresses.

This test locks in the existing round-trip contract at the daemon RPC boundary. It does not change RPC behavior or validate FCMP++ proofs. It makes future CARROT transaction serialization changes fail visibly if they break external consumers.

## Scope

Test-only change in `tests/functional_tests/transfer.py`.
