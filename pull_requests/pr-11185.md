# Original Description
fixes #9332

Wallet::store(), wallet close, transaction creation, signed transaction loading/submission, pending transaction broadcast/file saving, background-sync transitions, and multisig image import could run while refresh was mutating wallet state.

Suspend the active refresh, wait for wallet state to settle, perform the operation, then restore the previous auto-refresh state. Synchronous refresh and rescan calls return false only when suspension actually skips block or pool work, without emitting refreshed() for that attempt. Queued refresh and rescan requests stay pending until they can run. If a fetched pool batch is skipped, the next refresh requests a full pool snapshot so pool changes are not lost.

Operations that would acquire another refresh lock from a refresh callback or another guarded wallet operation return an error instead of risking reentrant or cross-wallet deadlocks. File-only commits remain allowed when the same wallet is already serialized.

This PR deliberately limits serialization to the operations listed above. Other wallet API readers and mutators remain outside this guard and should be handled separately.

tests:
- full libwallet_api_tests with GCC and Clang (59/59 each)
- full unit_tests (1308 passed, 2 skipped)
- focused concurrency, interruption, callback, nesting, and mutation regression tests
