# Original Description
Fixes #11222

pruned block sync reconstructs each transaction with the received prunable hash, but only the txid is cached. when the pruned transaction reaches the DB, its prunable payload is absent, so the DB has no authoritative prunable hash to store and falls back to recomputing it from incomplete data

cache the supplied hash when it participates in the reconstructed txid. `RCTTypeNull` is left unchanged because the supplied value is ignored there

reported and diagnosed by @meownero in #11222

tests:
- `build/tests/unit_tests/unit_tests --data-dir tests/data --gtest_filter='cn_format_utils.*'`
- `build/tests/unit_tests/unit_tests --data-dir tests/data`
