# Original Description
https://github.com/monero-project/monero/pull/5821 was rejected because it added runtime code to critical code path, so I'm suggesting this alternative. For security reasons it's only run on pull requests, the full tests are still run on merge.

Splitting up `core_tests` from the other tests also has the advantage that the more frequently failing tests run first.

Reduces `core_tests` runtime from 2610.67 sec to 273.01 sec (~90% reduction).

# Discussion History
## iamamyth | 2026-05-30T18:24:34+00:00
Fiddling with the source code (using sed, no less) makes the overall structure incredibly brittle; better to simply let the caller define a namespaced preprocessor macro (e.g. MONERO_CRYPTO_SLOW_HASH_ITER), which you can then default to `(1 << 20)` (i.e. the source continues to use `ITER`, it just makes the definition conditional).

## selsta | 2026-05-30T21:06:12+00:00
I thought about this but I did not find a way how to do this cleanly with CMake without adding `target_compile_definitions` to our CMake, which is something I wanted to avoid. Overall using `sed` seemed to be the least bad solution.

## iamamyth | 2026-05-31T18:14:35+00:00
`sed` is a terrible option because it means that syntactically valid code changes will break the replacement logic, slowing the test suite (i.e. effectively reverting the PR) without breaking the build. There are a lot of options to do this with cmake, `target_compile_definitions` could be part of the solution, although `add_compile_definitions` would allow for finer-grained scoping (i.e. the definition need not apply unconditionally to the target).
