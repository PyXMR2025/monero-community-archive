# Original Description
Since `lock.commit()` was not called here, the mempool meta updates weren't being committed to the database, but rather were aborted, as per the behavior of the destructor of `LockedTXN`. This meant that the `last_relayed_time` of txs was not being updated. This PR fixes this and also only attempts to open a write TXN if there are actualy changes to be made. It also defers opening the write TXN until later to improve concurrency.
