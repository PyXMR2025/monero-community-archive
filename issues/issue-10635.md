# Original Description
I've noticed on my more actively used public nodes Monerod will randomly hang for no reason. I've using log level 0 for privacy reasons so I don't get any detailed error messages. For instance, the end of my monerod log was as follows:
2026-05-21 04:23:04.319 [RPC0]  ERROR   cn      src/cryptonote_core/cryptonote_core.cpp:1277    Transaction not found in pool
2026-05-21 04:23:04.319 [RPC0]  ERROR   cn      src/cryptonote_core/cryptonote_core.cpp:1277    Transaction not found in pool
2026-05-21 04:23:04.320 [RPC0]  ERROR   cn      src/cryptonote_core/cryptonote_core.cpp:1277    Transaction not found in pool
After which my uptime monitor noticed that my node was not responding for over an hour. Running curl -v 127.0.0.1:18089/get_height on the server hosting the node has an open http connection that hangs and eventually times out. There are no dmesg warnings. After restarting monerod, RPC works again as expected.

This occurs probably once a month or two on my most active public nodes. It's probably some bug with Monerod, but as  run log level 0 I can't help much with debug data.

Some workarounds are to have a timer that restarts monerod daily or weekly running on your server that has the node. Alternatively, you can create a script that sends a curl request to the local ip RPC and sees if that fails a couple times in a row, then restart monerod.

It would be nice to have this internal heartbeat built in monerod, instead of needing to have a separate script run on the system.
Every couple of minutes, a separate thread should try to make a request for get_height on 127.0.0.1, if that timesout or fails successively multiple times, then restart monerod. We can add a check that monerod is currently not starting up, pruning the blockchain, or expanding the database file (as this might cause the RPC to fail, but that is only because the backend storage is doing an intensive task).
