# Original Description
## Summary

Follow-up for #332 after [#341](https://github.com/monero-project/monero-docs/pull/341) already removed stale `payment_id` / `set_payment_id` **fields** from the address-book methods.

This PR documents the **behaviour** that remains true in code:

- No separate payment-id RPC fields on `add_address_book` / `edit_address_book` / `get_address_book`
- Integrated addresses carry the payment ID in the `address` string
- `get_address_book` returns the integrated form when a payment ID was stored (see `on_get_address_book` reconstructing via `get_account_integrated_address_as_str`)
- Description-only `edit_address_book` keeps the existing payment ID (related core fix: monero-project/monero#10589)

## Changes

Short prose on the three methods + slightly clearer `address` bullets. No API fiction.

Closes #332
