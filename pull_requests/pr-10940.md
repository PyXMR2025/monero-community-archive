# Original Description
## Context

This addresses the stale remote-daemon connection failure reported in
https://github.com/haveno-dex/haveno/issues/1093 and follows the maintainer's
request to gather feedback at the Monero upstream level. The corresponding
release-v0.18 integration PR is https://github.com/haveno-dex/monero/pull/10.

On `nodex.monerujo.io:18081`, a successful HTTP/1.1 `get_info` response was
followed by a silent FIN after roughly five seconds of idle time, without a
`Connection: close` header. `blocked_mode_client::recv()` returned an empty
buffer on EOF without clearing `m_connected`, so the HTTP client kept treating
the half-closed socket as reusable. Depending on the next wallet RPC, this
surfaced as `Failed to get height`, `failed to get output distribution`, or
`no connection to daemon`.

## Changes

- mark `blocked_mode_client` disconnected on every read error, including EOF;
- add a loopback regression test covering data, FIN, disconnected state, and a
  successful new connection;
- disconnect once before the first `/get_outs.bin` chunk, after local ring
  member selection, so the next request reconnects lazily;
- reuse the `rct_config` and `use_view_tags` values already used to construct
  the transaction instead of querying fork rules again after proof generation.

The patch does not retry or replay a failed request, switch nodes, or change the
`sendrawtransaction` path. Broadcast reconnection remains covered separately by
https://github.com/monero-project/monero/pull/10862.

## Validation

- rebased as two focused commits on current `master`, touching three files;
- `git diff --check` passes;
- `src/wallet/wallet2.cpp` passes C++17 syntax and API compilation against the
  current upstream tree using the project's UCRT64 warning and include flags;
- `tests/unit_tests/net.cpp` passes the same C++17 syntax and API compilation;
- the equivalent release-v0.18 patch passed the Haveno fork's source, build,
  cross-toolchain, and Ubuntu test jobs. Upstream CI remains the authoritative
  execution check for this rebased patch.
