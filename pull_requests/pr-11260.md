This escapes the `bool` contract: `on_sign_multisig` / `on_submit_multisig` call `load_multisig_tx` outside a `try`, so wallet-rpc answers `{"code":0,"message":""}` (the validation on the next line can throw the same way). Catching here or in the two handlers fixes the first; if blocking non-importers isn't intended, skipping the tx-key store instead of throwing fixes the second (`commit_tx` stores the keys anyway on submit).
