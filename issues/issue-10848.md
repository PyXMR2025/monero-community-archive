# Original Description
Hello,

I was scanning the blockchain with my Python tools and my code got stuck on block `3698648`, more specifically on tx `bfb78ba8936bf1cd3b1883cb2568f4bf059c7fc1a81691b53bc0bd7ea154bcd3` because it could not correctly find the ring members for the CLSAG proof (as I was not limited by uint64 variables).

The key-offsets recorded on chain are those:
`"key_offsets": [ 157397969, 16660, 9681, 7938, 5385, 3831, 1437, 4950, 826, 813, 1237, 18446744073709482834, 18446744073709534619, 18446744073709550238, 18446744073709546177, 18446744073709183958]`

The benefits are that we avoid the introduction of some useless bytes in some txs and we avoid fungibility issues.

If you guys think that we should do that, I can draw a PR limiting relayed txs to only have monotonic key-offsets indices or something like that.
