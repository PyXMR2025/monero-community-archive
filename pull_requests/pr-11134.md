# Original Description
`wallet2::stop()` only sets a flag, which `refresh` checks between daemon RPC calls. If the current call is blocked on a stalled or unresponsive connection, the stop has no effect until the call hits the full RPC timeout (3.5 minutes by default), so stopping a wallet mid-refresh (with ctrl+c or invoking stop from CLI/RPC/natively) can hang for minutes, blocking progress to restart the wallet or shut down the application.

This PR makes `stop()` abort any in-flight daemon request by adding `shutdown()` to epee's http client. The epee override is safe to call from any thread. The base class default is a plain `disconnect()` for clients that don't support cross-thread interruption.

The new `shutdown()` just sets an atomic flag and wakes the blocked thread, which fails its request promptly and cleans up its own socket. The client reconnects transparently on next use, and shutdown is a no-op when no request is in flight, so idle connections (e.g. between CLI commands) are untouched.

As a result, wallets stop promptly and cleanly.
