# Original Description
Repro: send `Content-Length: 5abc` (or `0x10`, `+10`, `1 0`) to the embedded HTTP/RPC server; the request is accepted and the body length is taken from the leading digit run.
Cause: `get_len_from_content_lenght` matches `\d+` anywhere with `regex_search`, so a value that is not `1*DIGIT` (RFC 7230 3.3.2) is accepted, unlike the client path which already parses `Content-Length` with `string_tools::get_xtype_from_string`.
Fix: parse the whole value strictly with the same helper, rejecting any non-numeric `Content-Length`. Added a regression test in `tests/unit_tests/http.cpp` that fails before the change.
