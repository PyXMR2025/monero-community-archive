# Original Description
Currently, a node sets its peer connection's `m_remote_blockchain_height` during the handshake, initial sync, when syncing after falling out of sync, and in the `peer_sync_idle_maker`. It doesn't update it upon receiving a new bock.

The timed sync only runs once every 60s (`P2P_DEFAULT_HANDSHAKE_INTERVAL`). Thus, `m_remote_blockchain_height` can fall below our own node's actual height.

The peer connection's `m_remote_blockchain_height` is used to identify outgoing connections to relay txs to ([see `get_out_connections`](https://github.com/monero-project/monero/blob/1bf1dff4be4b2a604fd761b532e1c5aff4cc0bad/src/cryptonote_protocol/levin_notify.cpp#L151)). If the peer's height is less than ours, we don't relay txs to that peer.

Thus, without this PR, our node can avoid relaying txs to peers that technically are fine candidates to receive them.

This PR fixes the issue by updating the `m_remote_blockchain_height` as soon as the peer reports they receive (and validate a new block), and widens the window for candidate peers that we can relay to.
