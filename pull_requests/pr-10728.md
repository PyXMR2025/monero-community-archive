# Original Description
`import_key_images`, `import_outputs_from_str` and `import_multisig` read the `crypto::public_key`/`key_image`/`signature` fields straight off the decrypted blob through pointer casts, which is an aliased read and undefined behaviour. Noticed it going over the import paths after the levin buffer fix. Switched to memcpy into typed locals; the buffer lengths are already validated so the bytes read are unchanged.
