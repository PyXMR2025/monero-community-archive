# Original Description
# Fix Windows processor groups: NUMA memory binding + thread affinity for 64+ CPUs

## Problem

For the corner case of Windows systems with more than 64 logical processors (multiple processor groups), XMRIG's NUMA memory binding fails silently. The bundled hwloc handles processor groups correctly internally, but XMRIG's code paths use a cpuset round-trip conversion that breaks when bits span multiple groups. This causes RandomX dataset allocation to skip nodes or fall back to slow mode on multi-socket servers with 128+ cores.

Additionally, the non-hwloc fallback in `Platform_win.cpp` uses `SetThreadAffinityMask()` which cannot address CPUs beyond ID 63.

## Root Cause

hwloc's Windows backend converts cpusets via `hwloc_bitmap_to_single_ULONG_PTR()`, which returns -1 when bits span multiple processor groups (each group is a separate 64-bit mask). XMRIG called `membind()` with a nodeset passed as a generic bitmap, forcing an unnecessary cpuset round-trip before binding.

## Changes

### New `membind_nodeset()` API
- Added `hwloc_const_nodeset_t` typedef and new virtual method `membind_nodeset()` to `ICpuInfo` interface
- Implemented in `HwlocCpuInfo`, calling `hwloc_set_membind_nodeset()` directly — bypassing the cpuset round-trip entirely
- Renamed parameter in existing `membind()` from `nodeset` to `cpuset` for accuracy

### Fallback chain in callers
- **`RxNUMAStorage.cpp::bindToNUMANode()`**: tries `membind_nodeset(nodeset)` → `membind(cpuset)` → thread affinity only (last resort)
- **`VirtualMemory_hwloc.cpp::bindToNUMANode()`**: same two-tier fallback before returning node 0

### Non-hwloc Windows fix
- **`Platform_win.cpp`**: dynamically loads `SetThreadGroupAffinity()` for CPU IDs >= 64, falling back to `SetThreadAffinityMask()` for CPUs < 64

## Files Changed (6 source files)

|------|--------|

| `src/backend/cpu/platform/HwlocCpuInfo.h` | Declare `membind_nodeset()` override |

| `src/crypto/common/VirtualMemory_hwloc.cpp` | Use `membind_nodeset()`, add fallback chain |
| `src/base/kernel/Platform_win.cpp` | Handle CPU >= 64 via `SetThreadGroupAffinity()` |

## Backward Compatibility

- **Linux/macOS:** No change — direct nodeset binding succeeds wherever the old path did
- **Windows <64 CPUs:** No change — first fallback always succeeds
- **Windows 64+ CPUs with hwloc:** Fixed — correct NUMA binding on all processor groups
- **Windows 64+ CPUs without hwloc:** Fixed — threads correctly placed in higher groups

## Testing
- Compared stock v6.26.0 with a build including these modifications on Windows 11 systems with >64 threads
- Without the adjustments, thread memory failed to bind and datasets failed to load
- The build with the changes ran normally. Datasets properly loaded and mining hashrate was as expected for the tested maximum of 192 threads
- Linux build ran as before the modifications
