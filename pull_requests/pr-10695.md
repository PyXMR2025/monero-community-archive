# Original Description
### Summary

This fixes an HTTP Digest authentication interoperability issue in epee RPC servers.

Previously, server Digest auth state was stored in `http_custom_handler`. Since `http_custom_handler` is instantiated per TCP connection, a nonce generated in a `401 Unauthorized` challenge on one connection was not valid on another connection. This caused valid Digest retries to fail when clients, connection pools, or reverse proxies sent the authenticated retry over a different TCP connection.

This patch moves server Digest auth state to shared HTTP server config and tracks multiple outstanding nonces with per-nonce nonce-count replay protection.

### Behavior before this patch

With `monero-wallet-rpc --rpc-login user:<password>`:

- same TCP connection:
  - initial unauthenticated request gets `401`
  - authenticated Digest retry succeeds
- different TCP connection:
  - initial unauthenticated request gets `401`
  - authenticated Digest retry using the server-issued nonce gets `401 stale=true`

### Behavior after this patch

- same-connection Digest retry succeeds
- cross-connection Digest retry succeeds
- wrong password still fails
- wrong username still fails
- identical `Authorization` replay is rejected
- nonce state is bounded
- expired nonce state is pruned
- unused challenge nonces are evicted before active used nonces
- Digest verification is not performed while holding the nonce-state mutex
- unknown nonce handling does not expose the configured username via `stale=true` behavior

### Verification

Built successfully:

- `obj_epee`
- `monerod`
- `monero-wallet-cli`
- `monero-wallet-rpc`

Runtime probe against patched `monero-wallet-rpc`:

```text

cross-connection authenticated retry: HTTP 200 Ok
RESULT: FIXED / NOT REPRODUCED

cross_connection: HTTP 200

wrong_username: HTTP 401
replay_first: HTTP 200
replay_second: HTTP 401

latest_nonce_after_flood: HTTP 200
used_nonce_first_nc1: HTTP 200
used_nonce_second_nc2_after_flood: HTTP 200
```
