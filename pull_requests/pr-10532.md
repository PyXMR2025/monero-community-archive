# Original Description
Fixes #8741.

The wallet RPC method generate_from_keys has always rejected requests that omit the address field, even when spendkey and viewkey are provided. Docs describes address as required only when restoring a view-only wallet (no spend key). 

Issue #8741 reports two related problems:

1. Passing spendkey + viewkey without address is rejected, even though the address is fully determined by those keys.
2. When wrong address is passed alongside the keys, the wallet should error out rather than silently produce a broken wallet.

## Change
- address is now mandatory only when spendkey is empty (view-only-wallet case).
- When address is not present the spend and view public keys are derived from the supplied secret keys via secret_key_to_public_key, and the wallet is generated from the derived primary address.
- When address is supplied, the existing hwdev.verify_keys checks against the parsed address are preserved unchanged, so a mismatched address/keys combination still produces a clear error
- The response's address field continues to be populated from the generated wallet account, so callers always see address regardless of which input form they used.

The patch is contained to on_generate_from_key in wallet_rpc_server.cpp. No public API/contract changes as address is still accepted, the response shape is unchanged, and existing callers that send address see identical behaviour.
