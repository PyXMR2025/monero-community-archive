I don't really understand this change; the way it was before avoids subtracting from an unsigned value, and is generally more straightforward.

Something like `std::numeric_limits<size_t>::max()` could also be used to detect an underflow if needed.

## selsta | 2026-07-27T18:22:01+00:00
This can't underflow because `bin_data->size() >= PROTO_HEADER_SIZE` is being checked before. The change is because `msg_len` is `uint32_t` and `msg_len + PROTO_HEADER_SIZE` can wrap. It's not strictly needed but more secure this way.
