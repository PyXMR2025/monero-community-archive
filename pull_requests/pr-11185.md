# Original Description
fixes #9332

`Wallet::store()` could serialize the cache while refresh was mutating wallet state, which could crash or leave a corrupted cache

suspend and stop the active refresh, wait for the wallet state to become stable, store the cache, then resume automatic refresh if it was enabled. queued rescans stay pending until storage has completed

calls from a refresh callback return a useful error instead, since waiting from the same refresh thread would deadlock

tests:
- full release build
- full `libwallet_api_tests` after the final changes (40/40)
- 10 consecutive focused regression runs after the final changes
- full CTest excluding `core_tests` (23/23)
- `core_tests` (1/1)
