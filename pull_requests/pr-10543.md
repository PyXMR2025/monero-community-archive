# Original Description
Refs #10529.

## What

Adds `"get_transaction_pool"` to `blocked_in_restricted_mode` in [src/rpc/zmq_restricted_methods.cpp](../../blob/master/src/rpc/zmq_restricted_methods.cpp).
Restricted ZMQ callers receive `METHOD_NOT_FOUND` for this method.

The HTTP equivalent
([src/rpc/core_rpc_server.cpp:1709-1717](../../blob/master/src/rpc/core_rpc_server.cpp#L1709-L1717)) already zeros `receive_time` / `last_relayed_time` for restricted callers; the ZMQ handler at [src/rpc/daemon_handler.cpp:757-763](../../blob/master/src/rpc/daemon_handler.cpp#L757-L763) returns them verbatim. Both paths already filter to
`relay_category::broadcasted`, so stem-phase txs are not exposed either
way.

## Changes

- `src/rpc/zmq_restricted_methods.cpp` — bump array size 9 → 10, insert   `"get_transaction_pool"` between `get_peer_list` and `mining_status` (alphabetical order preserved so `check_blocked_methods_sorted()` keeps passing).
- `tests/unit_tests/zmq_rpc.cpp` — matching `EXPECT_TRUE` in `ZmqRestrictedMethods.BasicCoverage`.

## Test plan

- [x] `unit_tests` `ZmqRestrictedMethods.BasicCoverage` covers the new entry
- [x] Sort invariant preserved
- [ ] Manual: `monerod --restricted-zmq-rpc` → restricted ZMQ `get_transaction_pool` returns `METHOD_NOT_FOUND`
- [ ] Manual: unrestricted ZMQ port still serves it normally
- [ ] Manual: HTTP behavior unchanged on both ports
