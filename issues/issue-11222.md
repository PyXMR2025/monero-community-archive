# Original Description
I spent hours debugging why my code kept failing with parsed txid mismatch. I checked everything, then literally formatted the node’s disk and synced the whole blockchain again. Same error.

It looks like sync-pruned-blocks=1 is the problem. Monero receives the correct prunable_hash, uses it to validate the transaction, but doesn’t save it before writing to LMDB. It stores the hash of empty data (c5d246...) instead.

I think this line is missing from get_pruned_transaction_hash():

t.set_prunable_hash(pruned_data_hash);

The node reports itself as synchronized and healthy, but silently stores invalid transaction metadata.
