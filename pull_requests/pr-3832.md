# Original Description
 fix: multi-step NUMA memory binding fallback for Windows >64 CPUs
      
 On Windows with more than 64 logical processors, hwloc's membind functions
 can fail silently because they internally call SetThreadAffinityMask(), which
 only accepts a 64-bit mask (one processor group).
 
This PR adds a fallback cascade: nodeset membind → cpuset membind → cpubind via
SetThreadGroupAffinity() → thread affinity.

Also adds SetThreadGroupAffinity support in Platform_win.cpp for CPU >= 64,
and a hwloc_const_nodeset_t typedef needed by the new function signature.

Files changed:
- src/backend/cpu/interfaces/ICpuInfo.h — add hwloc_const_nodeset_t typedef
- src/backend/cpu/platform/HwlocCpuInfo.cpp — multi-step do_membind() fallback cascade
- src/base/kernel/Platform_win.cpp — SetThreadGroupAffinity for CPU >= 64
      
Backward Compatibility

- Linux/macOS: No change — direct nodeset binding succeeds wherever the old path did
- Windows <64 CPUs: No change — first fallback always succeeds
- Windows 64+ CPUs with hwloc: Fixed — correct NUMA binding on all processor groups
- Windows 64+ CPUs without hwloc: Fixed — threads correctly placed in higher groups

Testing
- Compared stock v6.26.0 with a build including these modifications on Windows 11 systems with >64 threads
- Without the adjustments, thread memory failed to bind and datasets failed to load
- The build with the changes ran normally. Datasets properly loaded and mining hashrate was as expected for the tested maximum of 192 threads
- Linux build ran as before the modifications
