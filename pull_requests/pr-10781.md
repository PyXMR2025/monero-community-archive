# Original Description
Multiple people have reported sporadic double spend errors on stressnet. @Rucknium's daemon and wallet logs helped me narrow down the cause* (EDIT: this still needs further investigation to identify the root cause).

### Before this PR

If a tx created by a wallet has been in the pool for >5mins, then the incremental logic might incorrectly think the tx has been kicked from the pool, even if the tx is still in the node's pool.

Then the wallet will mark the tx's key images as unspent, allowing the wallet to use the outputs in another tx. The subsequent tx then gets rejected by the node as a double spend, because the original tx is still in the node's pool.

### After this PR

This fixes the issue by assuming the node still has the already-seen tx in its pool unless the tx has been explicitly removed from the pool.
