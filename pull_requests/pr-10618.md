# Original Description
This part of the cache handing code assumed that A) the window size never changes, B) the window size is greater than or equal to the queried count, and C) that the cache container has an internal max size that is the size of the window. This PR fixes the behavior of `Blockchain::get_long_term_block_weight_median()` if none of those assumptions hold. This allows the long-term block median window size to be dynamic correctly. The handling of the LTM cache caused a consensus bug in the FCMP++ Beta Stressnet network, which shrunk the LTM window size at the v17 fork, but didn't resize the container.

Style note: the term "capacity" in the code may be suboptimal, especially if `epee::misc_utils::rolling_median_t<>` ever supports having a maximum size of the rolling values that differs from its allocated capacity. 

Relevant issue: https://github.com/seraphis-migration/monero/issues/390
