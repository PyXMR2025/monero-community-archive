## SNeedlewoods | 2026-07-05T13:52:49+00:00
Not really related to this PR, but a question for the Wallet API in general, when do we want to obsolete long payment ids there?

The wallet-cli already gives the following error when using `transfer <address> <amount> <long_payment_id>`:
```
Error: Error: Long payment IDs are obsolete.
Error: Long payment IDs were not encrypted on the blockchain and would harm your privacy.
Error: If the party you're sending to still requires a long payment ID, please notify them.
```
And for `transfer <address> <amount> <short_payment_id>`, i.e. giving a short payment id:
```
Error: Invalid last argument: <short_payment_id>
```

So there we allow short payment ids only in form of integrated addresses.
