# Original Description
Fix an uninitialized read in `BlockchainLMDB::get_tx_amount_output_indices` on the `MDB_NOTFOUND` branch.

`mdb_cursor_get` does not write to `*data` on `MDB_NOTFOUND` (see `mdb_cursor_set` in `external/db_drivers/liblmdb/mdb.c`). The fall-through reads uninitialized `v.mv_data` / `v.mv_size` on the first iteration, or stale prior-iteration data on later ones, then dereferences the cast pointer `v.mv_size / 8` times. Typical outcomes: crash on a bad pointer, or garbage indices returned to callers (`remove_tx_outputs`, `Blockchain::get_tx_outputs_gindexs`, and indirectly RPC handlers like `on_get_blocks`).

The existing warning text shows the author intended a defensive "log and continue" fallback; the implementation was just incomplete.

```cpp
MDB_val v;                                              // uninitialized
...
int result = mdb_cursor_get(m_cur_tx_outputs, &k_tx_id, &v, op);
if (result == MDB_NOTFOUND)
  LOG_PRINT_L0("WARNING: ...");                         // logs, falls through
else if (result)
  throw0(...);

op = MDB_NEXT;
const uint64_t* indices = (const uint64_t*)v.mv_data;   // UB on NOTFOUND
size_t num_outputs = v.mv_size / sizeof(uint64_t);      // UB on NOTFOUND
for (size_t i = 0; i < num_outputs; ++i)
  amount_output_indices.push_back(indices[i]);          // UB read
```
