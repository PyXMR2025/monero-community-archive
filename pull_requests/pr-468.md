# Original Description
There is a race in the libwallet API tests (and probably in the GUI too) where it appears the wallet attempts to close and store the wallet cache while the refresh thread is still executing (see `WalletTest2.WalletCallbackReceived`). This corrupts the wallet cache. Since FCMP++ introduced asserts that throw when the wallet state gets corrupted, corruption now fails loudly.

In this PR I make sure to synchronize the `store_to` call with the refresh thread.

Bonus: I call `m_wallet->shutdown()` before calling `m_wallet->store()` to make sure any block request network requests cancel first before grabbing the lock. IIRC sometimes the GUI can take a while to exit, this might help there.
