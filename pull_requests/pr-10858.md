# Original Description
Fixes #9930

`getblocktemplate` allows `reserve_size` up to 255, and tx-extra nonce lengths are encoded as varints

The returned `reserved_offset` still assumed the nonce length used one byte, so reserve sizes >= 128 pointed at the second varint byte instead of the reserved bytes

This uses the actual varint length when calculating the offset, and adds functional coverage for 1, 127, 128, and 255 byte reserves

Tests:
- `cmake --build build-sys --target monerod monero-wallet-rpc -j2`
- `/usr/bin/python3.13 tests/functional_tests/functional_tests_rpc.py /usr/bin/python3.13 tests/functional_tests build-sys blockchain`
- `git diff --check`
