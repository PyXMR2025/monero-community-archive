# Original Description
The core problem with D++ stalling is that P2P sending should never stall a thread. The only real fix (as argued by ZeroMQ authors, and others), is that you can buffer, reject data, or close stream. Stalling the thread defeats the purpose of leveraging ASIO in the first place, and doesn't fix the underlying issue.

This patch also changes some key differences in handling the max size constraints. Currently P2P connections are actually limited by 32 MiB due to "chunking", and the soft limit doesn't trigger correctly either. This changes both. If the remote peers does many small requests, the 32,000 chunk limit still applies.
