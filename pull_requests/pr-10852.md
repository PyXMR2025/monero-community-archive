# Original Description
Fixes #8947

`wallet2::is_deterministic()` derived the expected view key from the current in-memory spend key. For attended wallets using `AskPasswordToDecrypt`, `setup_keys()` encrypts that spend key in memory, so the check returned false even for deterministic wallets

This caches the deterministic state while keys are still plaintext, before `setup_keys()` encrypts them. `get_seed()` still checks the currently loaded keys directly, so it keeps refusing to export a seed while the spend key is locked

Tests:
- `cmake --build build-ap4sh-wallet --target unit_tests test_notifier -j2`
- `./build-ap4sh-wallet/tests/unit_tests/unit_tests --gtest_filter=notify.works:wallet_keys_unlocker.*`
- `ctest --test-dir build-ap4sh-wallet -R ^unit_tests$ --output-on-failure`
