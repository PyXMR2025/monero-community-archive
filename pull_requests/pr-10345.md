# Original Description
Builds on top of:
- #10342
- #10111
- #10135

When inserting outputs into the FCMP++ tree, we convert each output pubkey, key image generator, and commitment (ed25519 points) into Wei x and y coordinates (as part of the [tower cycle](https://gist.github.com/tevador/4524c2092178df08996487d4e272b096) critical for the curve tree -- Wei coordinates are "Selene" scalars).

This PR introduces the crypto functions necessary to perform the conversion:

- `point_to_ed_derivatives`
- `ed_derivatives_to_wei_x_y`
- `fe_ed_derivatives_to_wei_x_y`

It uses the equation from E.2 in https://www.ietf.org/archive/id/draft-ietf-lwig-curve-representations-02.pdf.

______

An earlier state of this PR was audited by Cypher Stack and Trail of Bits:
- Trail of Bits identified we were using the negative constant C from the paper on converting ed25519 to Wei coordinates.
  - Remediated and added a test that shows we're using the same hex constants from the paper.
  - Rust side also updated [here](https://github.com/monero-oxide/monero-oxide/commit/066229801a18bb11679113c93971c4f19fde0cd0).
- Both Cypher Stack and Trail of Bits pointed out a potential footgun if `fe_batch_invert` is called with a 0 value in `ed_derivatives_to_wei_x_y`.
  - Remediated by failing `ed_derivatives_to_wei_x_y` if so.
  - Cypher Stack section [8.4.3](https://github.com/cypherstack/fcmp-impl-audit/blob/d7de33d08c48a3c249629e47f71ea72c938a3404/FCMP_Code_Implementation_Audit.pdf).
- Trail of Bits recommended adding documentation to the conversion functions to be clear on expected input params.

All are remediated in the latest version of this PR. Will share the Trail of Bits audit once public.
