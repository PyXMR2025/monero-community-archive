# Original Description
## Context

On `nodex.monerujo.io:18081`, a successful HTTP/1.1 `get_info` response was
followed by a silent FIN after roughly five seconds of idle time, without a
`Connection: close` header. `blocked_mode_client::recv()` returned an empty
buffer on EOF without clearing `m_connected`, so the HTTP client kept treating
the half-closed socket as reusable.

## Root cause

The disconnected state was set only after the EOF branch returned. As a result,
EOF left `m_connected` set even though the peer had closed the socket.

## Changes

- mark `blocked_mode_client` disconnected on every read error, including EOF;
- add a loopback regression test covering data, FIN, disconnected state, and a
  successful new connection.

The transaction-construction changes formerly included here have been split
into #11093 following the maintainer's recommendation.

## Validation

- the branch now contains only the focused EOF commit and touches two files;
- `git diff --check` passes;
- the combined branch previously passed all 18 upstream CI checks; CI on this
  reduced branch is the authoritative check after the split.

Related downstream report: https://github.com/haveno-dex/haveno/issues/1093
