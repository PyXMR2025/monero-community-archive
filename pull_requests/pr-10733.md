# Original Description
## Summary
- use `memcpy` for AES block input/output word loads and stores instead of casting block bytes to `uint32_t *`
- keep expanded round-key reads on the direct word path through a `__may_alias__` word type
- make the expanded key parameter const to match the existing declarations

Related to #10076

## Testing
- `cmake --build build/debug-system --target cncrypto-tests monero-wallet-crypto-bench hash-tests hash-target-tests -j2`
- `ctest --test-dir build/debug-system --output-on-failure -R 'cncrypto|wallet-crypto-bench|hash-(fast|slow|slow-1|slow-2|slow-4)|hash-target'`
- `MONERO_USE_SOFTWARE_AES=1 ctest --test-dir build/debug-system --output-on-failure -R 'cncrypto|wallet-crypto-bench|hash-(fast|slow|slow-1|slow-2|slow-4)|hash-target'`
- `ctest --test-dir build/debug-system --output-on-failure -R 'cnv4-jit'`
- `cmake --build build/debug-noaes-system --target cncrypto-tests monero-wallet-crypto-bench hash-tests hash-target-tests -j2`
- `ctest --test-dir build/debug-noaes-system --output-on-failure -R 'hash-target|wallet-crypto-bench|cncrypto|hash-fast|hash-slow|hash-slow-1|hash-slow-2' -E '^hash-slow-4$'`
- `gcc -O2` and `clang -O2` object checks: same `aesb_single_round` and `aesb_pseudo_round` symbol sizes, no assembly diff vs `origin/master` except the object filename

Note: `hash-slow-4` still fails in the `NO_AES=ON` build with `Error generating CryptonightR code`; I checked the same failure on `origin/master` before restoring this patch
