# Original Description
This PR: #680 added a new fjall keyspace to keep track of the top hash in the fjall DB. We use this hash to check if we need to rebuild fjall. Newly created DBs wont have this field so we assume that empty tapes and fjall databases without the top hash are in sync. Old databases would rebuild fjall automatically.

This PR: #681 added pruning. With old databases the tapes database metadata would fail to read resetting the metadata to empty. This is fine, databases would resync automatically.

However this only works if you take each step individually old DB -> #680 -> #681 if you go old DB -> #681 then the fjall top hash wont be there _and_ the tapes will be empty, meaning the database would see them as being in sync when they are not.
