# Original Description
## Problem

A Ledger that is connected but has no app open is reported as:

```
No device found
```

That is also what an absent device reports.

The device is plugged in, powered, and often unlocked, and monero says it cannot find it.

## Why enumeration is not enough

A Ledger reports product id 0x0004 while the Monero app is running, and 0x4000 with no app open.

A device with no app open therefore matches none of `known_devices` and never reaches the transport.

The product id is the same whether that device is locked or sitting on its dashboard, so enumeration cannot tell those two states apart. They need different advice.

## Change

When none of `known_devices` matches but a Ledger is present, ask the Ledger OS which application is running.

A locked device answers `SW_LOCKED_DEVICE` to any command. An unlocked one answers from its dashboard.

That gives:

* `Ledger is locked.` when the device is locked
* `Open the Monero app on your Ledger.` when it is unlocked with no app open

The query runs only after `known_devices` has already failed to match.

A device with the Monero app open never reaches it, so its behaviour is unchanged.

Based on #10997, which defines `SW_LOCKED_DEVICE`.
