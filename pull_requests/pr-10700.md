# Original Description
Noticed wallet2::generate reads the multisig restore blob through `*(uint32_t*)` and `*(crypto::secret_key*)` casts straight off the byte buffer, which is an aliased read and undefined behavior. Switched them to memcpy into typed locals, the same change made recently for the levin buffer reads.

# Discussion History
## vtnerd | 2026-06-11T19:10:44+00:00
This should call `unwrap(unwrap(spend_secret_key))`. I think some compilers give warnings about this now, as `secret_key` is not trivial copyable.

## alhudz | 2026-06-12T04:19:22+00:00
Done, switched all three `secret_key` reads to `memcpy(&unwrap(unwrap(...)), ...)`, same as `chacha.h` does for `chacha_key`. The `public_key` ones are left as-is since `ec_point` is trivially copyable.
