# Original Description
the current check only rejects a hash when both its length and character set are invalid, so hashes such as short alphanumeric strings or 64-character non-hex strings can pass

this parses the field as a 32-byte hash instead, rejecting malformed records before version selection and normalizing valid uppercase input for downstream SHA-256 comparisons

the downloaded file is still hashed and checked independently as before

tests:
- `cmake --build build-gcc --target common -j2`
- `cmake --build build-gcc --target unit_tests -j2`
- `ctest --test-dir build-gcc -R '^unit_tests$'` (1315 tests, 1313 passed, 2 skipped)
- focused parser checks for lowercase, uppercase, invalid hex, wrong lengths, and empty input
- live `monerod update check` against the current MoneroPulse records
- `git diff --check`
