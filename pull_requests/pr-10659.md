# Original Description
### Marking as draft for now. This PR:

  * Adds msgpack output (writer) to the `::wire` serialization system
  * Adds block+transaction output support to the `::wire` serialization system
  * Switches all `ZMQ-PUB `output to use `::wire` serialization system (instead of just select few)
  * Adds msgpack output to all existing `ZMQ-PUB` subscription options
  * Passes existing tests but msgpack verification has not been added yet (see `Feedback` section below).

### Needs (before marking ready):
  * A system to signal which subscription types are supported
  * More testing to ensure tx compatibility.

### Feedback

@SChernykh @tevador @kayabaNerve @jeffro256 @j-berman  (sorry for tags but this is the critical part):

Should cbor be used instead of msgpack? I had a msgpack output lying around already, thus I leveraged it quickly for this PR. However, @kayabaNerve has expressed favoritism toward cbor (which has slightly more complex readers due to array design). I could even do both, as the vtable interface should keep exe size minimal.

### Future
Integer keys could theoretically be added which will compress serialization size and may be slightly quicker on both reads and writes (would have to test to verify its worth the hassle).
