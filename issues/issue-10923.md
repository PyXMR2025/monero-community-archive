# Original Description
## Environment

-   Monero GUI: v0.18.5.0 (Fluorine Fermi)
-   monero-wallet-cli: v0.18.5.0
-   Monero daemon: v0.18.4.6
-   Linux Mint
-   Mainnet
-   Private Umbrel node
-   Private authenticated RPC connection
-   Wallet connected through authenticated RPC

------------------------------------------------------------------------

## Problem

I created an outgoing transaction of **2.775862969968 XMR**.

The wallet successfully created a transaction with the following TXID:

``` text
fd3cc6805eff6bb1ca36a1f285193e741ba9cf85331b8b98cc8570fa980a00f3
```

The GUI still shows the transaction as:

-   Pending
-   0/10 confirmations

However:

-   the transaction never appeared on the network
-   the TXID cannot be found on any Monero explorer
-   the recipient (FixedFloat) never received anything
-   the daemon mempool does not contain the transaction
-   the wallet balance stays at **0 XMR** because the outputs remain
    locked

## Important observation

After restoring the wallet from the original seed:

-   the restored wallet has exactly the same primary address
-   the restored wallet contains the complete transaction history
-   the restored wallet also contains exactly the same pending
    transaction
-   the TXID is identical
-   the transaction is still pending
-   the outputs remain locked

The pending transaction survives a complete wallet restore.

-   still considers the transaction pending

## mithat-maker | 2026-07-16T19:33:02+00:00
Thank you!

Running `flush_txpool` via the daemon JSON-RPC solved the issue.

I executed:

```bash
curl --digest \
  -u monero:<hidden> \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":"0","method":"flush_txpool"}' \
  http://127.0.0.1:18081/json_rpc
```

The daemon returned:

```json
{
  "id":"0",
  "jsonrpc":"2.0",
  "result":{
    "status":"OK",
    "untrusted":false
  }
}
```

After reconnecting the wallet and refreshing:

- the wallet balance became fully unlocked again
- `show_transfers pending` is now empty
- `show_transfers failed` now contains the transaction
- the transaction is no longer considered pending

The funds are available again.

Thank you very much for your help!
